# DATA_MODEL.md — Nocturne

> **Status:** M0 Draft — last updated 2026-10-17  
> **Stability:** Schema v0. Migrations must be added for every change after first deploy.

---

## 1. Storage Location

SQLite database file: `{app_data_dir}/Nocturne/nocturne.db`

- Resolved by Tauri's `app_data_dir()` → typically `C:\Users\<name>\AppData\Roaming\Nocturne\`
- Never co-located with the original PDF files
- WAL journal mode enabled for concurrent read access
- Foreign keys enabled: `PRAGMA foreign_keys = ON` on every connection

---

## 2. Migration Strategy

Migrations run at application startup before any other DB access.

```typescript
// src/services/db/migrations.ts
const MIGRATIONS: Migration[] = [
  { version: 1, sql: CREATE_TABLES_V1 },
  // future: { version: 2, sql: ALTER_TABLE_... },
];
```

Rules:
- Migrations are append-only — never modify a past migration
- Each migration runs in a transaction; failure rolls back and the app fails fast with a clear error
- DB schema version tracked in `_meta` table
- No destructive schema changes without a migration version bump and data-preservation script
- Backups must be taken before applying migrations in release builds (prompted to user)

### 3.2 `documents`

One row per imported PDF. The original PDF is never modified.

```sql
CREATE TABLE IF NOT EXISTS documents (
  id              TEXT PRIMARY KEY NOT NULL,  -- UUID v4, stable identity
  file_path       TEXT NOT NULL,              -- Absolute path at import time
  file_size_bytes INTEGER NOT NULL,
  fingerprint     TEXT NOT NULL,              -- SHA-256 of first 64 KB + file size
  title           TEXT,                       -- From PDF metadata or filename
  author          TEXT,                       -- From PDF metadata, nullable
  page_count      INTEGER,                    -- From PDF.js on load, nullable until parsed
  import_status   TEXT NOT NULL DEFAULT 'pending',
                                              -- 'pending' | 'ready' | 'error' | 'fingerprint_mismatch'
  error_message   TEXT,                       -- Populated on import_status = 'error'
  created_at      TEXT NOT NULL,              -- ISO 8601 UTC
  updated_at      TEXT NOT NULL,              -- ISO 8601 UTC

  CONSTRAINT documents_fingerprint_unique UNIQUE (fingerprint),
  CONSTRAINT documents_status_check CHECK (
    import_status IN ('pending', 'ready', 'error', 'fingerprint_mismatch')
  )
);

CREATE INDEX idx_documents_created_at ON documents(created_at DESC);
```

**Notes:**
- `id` is generated by the application (UUID v4), not an auto-increment integer — this ensures stable references if the DB is exported and re-imported.
- `fingerprint` uses SHA-256 of the first 64 KB + the file's total byte count. This is fast and sufficient to detect most duplicate imports. It is not a cryptographic guarantee.
- `file_path` can become stale if the user moves the PDF; the app checks existence on open.
- `UNIQUE(fingerprint)` prevents duplicate imports; duplicate detection shown to user as a warning, not a silent drop.

### 3.3 `reading_progress`

One row per document, updated as the user reads.

```sql
CREATE TABLE IF NOT EXISTS reading_progress (
  document_id     TEXT PRIMARY KEY NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
  page_index      INTEGER NOT NULL DEFAULT 0,   -- 0-based PDF page index
  scroll_top      REAL NOT NULL DEFAULT 0.0,    -- Fractional scroll offset within page (0.0–1.0)
  zoom_level      REAL NOT NULL DEFAULT 1.0,    -- e.g., 1.0 = 100%
  reading_mode    TEXT NOT NULL DEFAULT 'default',
                                                -- 'default' | 'focus'
  last_opened_at  TEXT NOT NULL,               -- ISO 8601 UTC
  updated_at      TEXT NOT NULL,               -- ISO 8601 UTC

  CONSTRAINT reading_progress_mode CHECK (
    reading_mode IN ('default', 'focus')
  )
);
```

**Notes:**
- `page_index` is the 0-based PDF page index as reported by PDF.js.
- `scroll_top` is normalized: 0.0 = top of page, 1.0 = bottom of page. Stored as a fraction so it is independent of window height and zoom level. On restore, scroll position is approximated — exact pixel position is not guaranteed across zoom changes.
- Save strategy: debounce scroll/zoom events with a 500ms delay; persist immediately on: page turn, annotation commit, app close, window resize end.

### 3.4 `bookmarks`

Named page markers created by the user.

```sql
CREATE TABLE IF NOT EXISTS bookmarks (
  id          TEXT PRIMARY KEY NOT NULL,   -- UUID v4
  document_id TEXT NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
  page_index  INTEGER NOT NULL,            -- 0-based PDF page index
  scroll_top  REAL NOT NULL DEFAULT 0.0,  -- Fractional position on the page
  label       TEXT,                        -- Optional user-provided label, max 200 chars
  created_at  TEXT NOT NULL,
  updated_at  TEXT NOT NULL,

  CONSTRAINT bookmarks_label_length CHECK (label IS NULL OR length(label) <= 200)
);

CREATE INDEX idx_bookmarks_document_page ON bookmarks(document_id, page_index);
```

### 3.5 `annotations`

Highlights (with optional notes) anchored to PDF page content.

```sql
CREATE TABLE IF NOT EXISTS annotations (
  id              TEXT PRIMARY KEY NOT NULL,   -- UUID v4
  document_id     TEXT NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
  page_index      INTEGER NOT NULL,            -- 0-based PDF page index
  
  -- Anchor geometry (PDF coordinate space)
  -- PDF coordinate origin is bottom-left; units are PDF points (1 pt = 1/72 inch)
  -- Stored as a JSON array of rect objects: [{"x":n,"y":n,"width":n,"height":n}, ...]
  -- Multiple rects handle multi-line selections
  rects_json      TEXT NOT NULL,

  -- Text anchoring
  selected_text   TEXT NOT NULL,               -- Verbatim selected text, max 500 chars
  anchor_prefix   TEXT,                        -- Up to 100 chars before selection
  anchor_suffix   TEXT,                        -- Up to 100 chars after selection

  -- Appearance
  color           TEXT NOT NULL DEFAULT 'amber',
                                               -- 'amber' | 'teal' | 'violet' | 'rose'

  -- Optional note
  note_content    TEXT,                        -- User-written note, max 4000 chars

  -- Metadata
  is_deleted      INTEGER NOT NULL DEFAULT 0, -- Soft-delete (1 = deleted)
  created_at      TEXT NOT NULL,
  updated_at      TEXT NOT NULL,

  CONSTRAINT annotations_color_check CHECK (
    color IN ('amber', 'teal', 'violet', 'rose')
  ),
  CONSTRAINT annotations_selected_text_length CHECK (length(selected_text) <= 500),
  CONSTRAINT annotations_note_length CHECK (note_content IS NULL OR length(note_content) <= 4000)
);

CREATE INDEX idx_annotations_document_page ON annotations(document_id, page_index)
  WHERE is_deleted = 0;
CREATE INDEX idx_annotations_document ON annotations(document_id)
  WHERE is_deleted = 0;
```

**Coordinate system documentation:**
- PDF.js reports text positions in PDF user space coordinates (origin: bottom-left, units: points).
- All `rects_json` values are stored in this native PDF coordinate space, not in screen pixels.
- On render, the application transforms PDF coordinates to screen coordinates using the current page viewport (`page.getViewport({ scale })`).
- This means anchor geometry is zoom-independent — changing zoom changes the transform, not the stored coordinates.

**Multi-line highlight:** A highlight spanning multiple lines produces multiple rect objects in `rects_json`. The overlay renderer draws each rect independently.

**Soft delete:** `is_deleted = 1` hides the annotation from all queries without losing it immediately. A hard-delete sweep can be run on export or scheduled cleanup. This enables undo within a session.

### 3.6 `reading_sessions`

One row per contiguous reading session.

```sql
CREATE TABLE IF NOT EXISTS reading_sessions (
  id              TEXT PRIMARY KEY NOT NULL,  -- UUID v4
  document_id     TEXT NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
  started_at      TEXT NOT NULL,             -- ISO 8601 UTC
  ended_at        TEXT,                      -- NULL if session ongoing
  duration_seconds INTEGER,                  -- Computed on close; NULL if interrupted
  first_page      INTEGER NOT NULL,
  last_page       INTEGER NOT NULL,
  pages_visited   TEXT NOT NULL DEFAULT '[]' -- JSON array of visited 0-based page indices
);

CREATE INDEX idx_sessions_document ON reading_sessions(document_id, started_at DESC);
```

### 3.7 `agent_threads`

A conversation thread associated with a document.

```sql
CREATE TABLE IF NOT EXISTS agent_threads (

  document_id TEXT NOT NULL REFERENCES documents(id) ON DELETE CASCADE,

  CONSTRAINT agent_threads_mode CHECK (
    mode IN ('explain', 'connect', 'challenge', 'apply')

CREATE INDEX idx_agent_threads_document ON agent_threads(document_id, updated_at DESC);
```

### 3.8 `agent_messages`

Individual turns in a thread.

```sql
CREATE TABLE IF NOT EXISTS agent_messages (
  id              TEXT PRIMARY KEY NOT NULL,  -- UUID v4
  thread_id       TEXT NOT NULL REFERENCES agent_threads(id) ON DELETE CASCADE,
  role            TEXT NOT NULL,             -- 'user' | 'assistant' | 'system'
  content         TEXT NOT NULL,             -- Message body; never contains secrets
  -- Source references: JSON array of {page_index, text_snippet, confidence}
  source_refs     TEXT NOT NULL DEFAULT '[]',
  status          TEXT NOT NULL DEFAULT 'complete',
                                             -- 'streaming' | 'complete' | 'error'
  created_at      TEXT NOT NULL,

  CONSTRAINT agent_messages_role CHECK (role IN ('user', 'assistant', 'system')),
  CONSTRAINT agent_messages_status CHECK (status IN ('streaming', 'complete', 'error'))
);

CREATE INDEX idx_agent_messages_thread ON agent_messages(thread_id, created_at ASC);
```

### 3.10 `document_chunks`

Extracted text segments for retrieval by the Context Beacon.

```sql
CREATE TABLE IF NOT EXISTS document_chunks (
  id          TEXT PRIMARY KEY NOT NULL,   -- UUID v4
  document_id TEXT NOT NULL REFERENCES documents(id) ON DELETE CASCADE,
  page_index  INTEGER NOT NULL,
  chunk_index INTEGER NOT NULL,            -- Position within the page
  content     TEXT NOT NULL,              -- Extracted text content
  char_count  INTEGER NOT NULL,
  created_at  TEXT NOT NULL,

  CONSTRAINT document_chunks_unique UNIQUE (document_id, page_index, chunk_index)
);

CREATE INDEX idx_chunks_document_page ON document_chunks(document_id, page_index);

-- Full-text search virtual table (FTS5)
CREATE VIRTUAL TABLE IF NOT EXISTS document_chunks_fts USING fts5(
  content,
  document_id UNINDEXED,
  page_index UNINDEXED,
  chunk_index UNINDEXED,
  content=document_chunks,
  content_rowid=rowid
);
```

## 5. Data Integrity Rules

1. All entity IDs are UUIDs generated by the application — not auto-increment integers. This ensures stable cross-device identity for export/import.
2. All timestamps are ISO 8601 UTC strings (e.g., `2026-10-17T14:30:00.000Z`).
3. Foreign keys enforced; CASCADE DELETE on document removal propagates to all related entities.
4. Soft-delete pattern used for annotations (session-level undo); hard-delete on explicit user action.
5. No raw JSON blobs except: `rects_json` (geometry), `source_refs` (citation list), `pages_visited` (session summary). These are validated on write and parsed on read with typed zod/schema checks.
6. Writes to annotations are immediate (no debounce); scroll/zoom progress is debounced 500ms.
7. All multi-step writes use explicit SQLite transactions.

## 6. Export / Import Format

Export produces a JSON file:

```json
{
  "export_version": 1,
  "exported_at": "2026-10-17T14:30:00.000Z",
  "app_version": "0.1.0",
  "documents": [...],
  "reading_progress": [...],
  "bookmarks": [...],
  "annotations": [...],
  "reading_sessions": [...],
  "agent_threads": [...],
  "agent_messages": [...],
  "thought_trails": [...],
  "thought_trail_items": [...]
}
```

**Import rules:**
- Validate `export_version` and `app_version` compatibility on load.
- Detect ID conflicts: prompt user to merge or replace.
- Never import agent message content that looks like system prompt injection (validate structure).
- After import, run a consistency check: all FKs resolvable, no orphaned chunks.
- Import does not overwrite an existing DB without explicit user confirmation.

## 7. Backup

Manual backup: copy `nocturne.db` to a user-chosen location (triggered from Settings).
Restore: copy backup over `nocturne.db` on next launch (with confirmation and current DB archived first).
Auto-backup: not in M0–M2; evaluate for M5.
